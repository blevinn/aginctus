# Aginctus v0.1.0

Aginctus v0.1.0 provides a **single-host, operator-managed NixOS/Incus environment** for running coding agents through Herdr and a private AI gateway.

## Highlights

- **Managed coding workloads:** Provision Herdr and OpenCode containers, manage persistent SSH identity and host trust, and launch and control agents through Herdr.
- **Private inference gateway:** Deploy LiteLLM with PostgreSQL, register model aliases, issue scoped and revocable workload keys, and route OpenCode requests through the management network. Selective OpenCode Go Responses forwarding preserves native session metadata.
- **Host integration and network controls:** NixOS module and CLI, managed Incus networks, default-route-free management guests, separate LiteLLM egress, dynamic DNS/DHCP firewall integration, and guarded credential provisioning.
- **Development and diagnostics:** Reproducible Nix builds, read-only health and configuration checks, structured tests, and disposable-VM validation tools.

## Compatibility and upgrades

v0.1 targets a trusted, single-operator **x86_64 NixOS host with Incus**. The packaged workloads are containers, not independent VMs. NixOS packaging is preferred; a Linux amd64 CLI archive is also available as a release artifact.

Existing development deployments need a reviewed migration plan. Preserve Herdr identities, gateway/DB state, image references, and secrets when changing versions. Reverting a Nix pin does not undo changes to live Incus or gateway state.

## Validation and security evidence

Live pilot testing confirmed **Herdr-managed OpenCode source edits, test execution, completion, and authenticated upstream inference through the private LiteLLM gateway**. Scoped-key revocation and cleanup of owned workspaces and credentials were independently checked. Disposable VM tests also exercised the real gateway deployment and service readiness.

**Known limitations:** A complete deployment, coding smoke, cleanup, and repeat on a fresh NixOS host was **not validated** in v0.1 (deferred to [v0.2 #580](https://github.com/blevinn/aginctus/issues/580)). The management network is shared; workload keys use private-network HTTP, and containers share the host kernel. Existing selective gateway state must not be automatically reconciled without review. Full routed-IPv6 enforcement, disruptive live firewall recovery, independent provider billing, and publisher provenance were not established. v0.1 is not a production-hardened multi-tenant platform.

For technical evidence and operational guidance, see [release acceptance](https://github.com/blevinn/aginctus/issues/118), the [deployment runbook](../v0.1-deployment-acceptance.md), and [security limitations](../security.md).
