# Aginctus v0.2.0 — working release notes

> **Development draft (2026-11-08): not a published release, a release candidate, or acceptance sign-off.** The running development version is `0.2.0-dev`. A merged feature slice proves only the scope of its own tests. Remove this working-status section and resolve every release gate before publishing. Authoritative release scope and disposition: [#173](https://github.com/blevinn/aginctus/issues/173) and [v0.2 milestone](https://github.com/blevinn/aginctus/milestone/2).

v0.2 is advancing Aginctus from a single-host pilot toward an operator-managed, project-scoped NixOS/Incus agent environment with native reconciliation, an increasingly declarative gateway, and reproducible acceptance tooling. **That destination has not yet been demonstrated end to end.**

## Highlights — merged foundations, not release acceptance

- **Structured CLI:** The command-line surface has migrated to typed Cobra subcommands, generated help, syntax/error parity tests, and a reorganized command hierarchy. The dedicated worker tools are converging behind `aginctus-testenv` ([#372](https://github.com/blevinn/aginctus/issues/372), [PR #647](https://github.com/blevinn/aginctus/pull/647)).
- **Native Incus building blocks:** The official Incus Go SDK now underpins guarded project, bridge, and scoped-instance planning and selected lifecycle/reconciliation paths, with ownership and real-Incus VM tests. Native gateway deployment, cross-resource lifecycle parity, and legacy backend retirement are **not complete** ([#153](https://github.com/blevinn/aginctus/issues/153), [PR #679](https://github.com/blevinn/aginctus/pull/679)).
- **Home Manager operator foundations:** Standalone user installation and normalized nonsecret configuration, read-only authority and state diagnostics, NixOS host-only firewall boundaries, and VM coverage for switching and recovery are in the tree. Privileged operations remain host-owned; user image/reconciler activation and reversible cutover still require validation ([#426](https://github.com/blevinn/aginctus/issues/426)).
- **Gateway and MCP configuration:** Provider-plugin and catalog declarations, Nix-projected nonsecret gateway model/provider settings, and normalized MCP registry/grant policy with redacted effective inspection are implemented in part. Declarations are **not** equivalent to enforced MCP access or converged live gateway registrations ([#496](https://github.com/blevinn/aginctus/issues/496), [#162](https://github.com/blevinn/aginctus/issues/162)).
- **ChatGPT sign-in groundwork:** Initial protected credential ownership, validated enrollment, LiteLLM-side refresh, and Responses transport components have merged. The remaining managed-route, lifecycle integration, negative-path, and live acceptance work still gates availability ([#187](https://github.com/blevinn/aginctus/issues/187), [PR #689](https://github.com/blevinn/aginctus/pull/689)).
- **Validation and test environments:** A typed Go test catalog/runner, concise redacted JSON reporting, private VM evidence reader, synthetic full-stack fixtures, and isolated worker/VM recovery foundations improve repeatability. Synthetic tests do **not** establish real provider inference or fresh-host deployment acceptance ([#630](https://github.com/blevinn/aginctus/issues/630), [#475](https://github.com/blevinn/aginctus/issues/475), [#580](https://github.com/blevinn/aginctus/issues/580)).
- **Developer workflow and docs:** CI now has independent Go/static lanes and safer main-run retention while the original required hermetic gate remains in place. Documentation is being consolidated into explicit current-operation, evidence, design, and historical sections ([#705](https://github.com/blevinn/aginctus/issues/705), [#645](https://github.com/blevinn/aginctus/issues/645)).

## Compatibility and upgrades (provisional)

The inherited v0.1 baseline targets a trusted **x86_64 NixOS host with Incus**. Do not imply broader supported platforms or a production multi-tenant security posture without new evidence. Home Manager user configuration and NixOS root-host integration have different authority; a user configuration does not grant Incus-admin or firewall privileges.

There is **no blanket automatic upgrade/migration promise** for existing pilot deployments. Preserve PostgreSQL, gateway credential and model state, Herdr SSH identity, workload volumes and image references. Preview native project moves and root/user ownership transfers before any write; require explicit operator approval, recoverable backups and ownership/no-adoption checks. Pinning an older Git revision does not roll back already changed Incus or credential state. Follow the security and migration gates in [#198](https://github.com/blevinn/aginctus/issues/198) and [#426](https://github.com/blevinn/aginctus/issues/426).
