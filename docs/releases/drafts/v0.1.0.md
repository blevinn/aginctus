## Highlights

Aginctus v0.1.0 delivers the foundations for a **single-host,
operator-controlled NixOS/Incus agent lab**: a dedicated Herdr client manages
an OpenCode coding agent that reaches a private LiteLLM/PostgreSQL inference
gateway. The October 28 pilot demonstrated **real model-driven source edits,
test execution, authenticated upstream inference, and cleanup**. Five of six
top-level functional criteria in [release acceptance #118](https://github.com/blevinn/aginctus/issues/118)
are checked; reproducible fresh-host deployment/smoke and final release
approval remain outstanding.

Key capabilities:

- **Managed agent lifecycle:** The Aginctus CLI and NixOS module provision and
  plan owned Incus networks, guests, images and persistent state, with
  separately authorized reconciliation. A dedicated Herdr client uses
  persistent SSH identity, pinned host trust and a controlled OpenCode launch
  path. Two real Herdr-managed coding runs completed and cleaned up.
- **Private model gateway:** LiteLLM/PostgreSQL provisioning, private
  management access, protected provider/master credentials, model-alias
  registration and revocable, model-scoped workload keys. Narrow, default-off
  OpenCode Go Responses forwarding preserves the required native session and
  User-Agent metadata without enabling broad header passthrough.
- **Network and credential safeguards:** A non-NAT, nonrouting management
  bridge with no default gateway advertised to management-only guests;
  separate guarded LiteLLM egress; dynamic Incus DNS/DHCP firewall integration;
  ownership checks and fail-closed guest provisioning. Scoped live pilot
  controls passed, subject to the security limitations below.
- **Patched native CLI completion:** The source-patched pinned OpenCode passes
  unchanged terminal-text/stop assertions for incremental and one-write buffered
  SSE, directly and through pinned LiteLLM plus disposable PostgreSQL (#542).
- **Reproducible development and operator tooling:** Nix packaging, read-only
  diagnostics, structured hermetic/VM checks, documented operational
  procedures and human-gated release automation.

## Compatibility and upgrades

- **Intended environment:** A trusted, single-operator Linux/NixOS host with
  flakes and a local Incus installation. Bundled Herdr/OpenCode images are
  NixOS **containers**, not an independently qualified OpenCode VM or
  cross-platform workload runtime.
- **Distribution:** The Nix package/module is preferred on NixOS. Once
  approved and tagged, the release workflow creates a standalone **Linux
  amd64 CLI** archive and SHA256 checksums. No release archive has yet been
  published; ARM binaries, signed artifacts and SLSA provenance are not
  promised for v0.1.
- **Configuration and authority:** Incus, gateway and NixOS host-firewall
  reconciliation have separate controls. Firewall reconciliation may mutate
  host policy when explicitly enabled. The pilot's manually validated
  selective gateway configuration still differs from its host declaration;
  the reconciler hold must remain until a separately reviewed convergence
  plan is approved. General provider/model desired-state reconciliation and
  ChatGPT OAuth are not v0.1 requirements.
- **Existing installations:** The management-network DHCP policy now
  explicitly suppresses the default gateway, and OCI management NICs use
  internal on-link attachments ([#574](https://github.com/blevinn/aginctus/pull/574)).
  Existing pilots require a reviewed migration/rollback plan; normal
  reconciliation rejects incompatible legacy network policy rather than
  silently changing it. Preserve Herdr SSH identity, gateway/DB state,
  protected secrets, pinned images and workload credentials.
- **Upgrade boundary:** This is the first release, not a supported automatic
  migration path from arbitrary development snapshots. Pin the eventual
  immutable `v0.1.0` tag deliberately. Reverting a Nix flake pin does not
  revert live Incus resources, database state or issued credentials.

### Known limitations

- The trusted host/Incus administrator is within the security boundary.
  NixOS containers share the host kernel, and the management network is
  shared rather than per-workload segmented. Workload bearer keys traverse
  the private management bridge over HTTP. This is an operator-controlled
  pilot, **not** a production-hardened multi-tenant or audited security
  platform.
- The live pilot's selective gateway/image state was approved and checked
  manually; routine host declarative convergence is still held. Do not
  remove that hold, change host policy, rotate credentials or restart the
  gateway simply to validate the release notes.
- The versioned operator [deployment/acceptance handoff](../../v0.1-deployment-acceptance.md)
  was merged in #578, covering pinned inputs, staged activation, private state,
  manual coding, repeat/recovery and independently checked teardown. Its
  component/hermetic validation passed; a complete fresh-host
  deploy/smoke/repeat execution remains pending. On October 30, the release
  owner accepted the bounded legacy inspector, independent billing/provenance,
  live disruptive-recovery, IPv6/verdict-attribution and synthetic fault-test
  limits for v0.1. These are documented residual risks, **not** new PASS results.
- Later-release capabilities, including general gateway reconciliation,
  ChatGPT OAuth and dedicated Incus-project orchestration, are outside
  v0.1's supported scope. Separately merged opt-in disposable VM testenv
  infrastructure remains experimental; its combined nine-phase full-stack
  synthetic scenario is incomplete and deferred ([#531](https://github.com/blevinn/aginctus/issues/531)).
  It is not a substitute for the verified live pilot or a released feature.
