## Highlights

Aginctus v0.1.0 is intended to establish a **single-host, operator-controlled
NixOS/Incus agent lab** in which a dedicated Herdr client manages an OpenCode
workload and the workload uses a private LiteLLM/PostgreSQL gateway for model
inference. Final release depends on the independently verified workflow in
[release acceptance #118](https://github.com/blevinn/aginctus/issues/118).

The implemented foundations include:

- **Managed agent lifecycle:** Aginctus CLI and NixOS module support owned
  Incus networks, containers, persistent state, image preparation, status,
  planning, and explicitly authorized reconciliation. Herdr uses a dedicated
  client guest, persistent SSH identity, pinned workload SSH host trust, and a
  controlled OpenCode launch path.
- **Private inference gateway:** Aginctus can provision LiteLLM and PostgreSQL
  with separated protected gateway secrets, a private management endpoint,
  provider/model registration helpers, revocable model-scoped workload keys,
  and explicit delivery of the workload's key/configuration to its guest.
  Real upstream inference remains an open acceptance gate.
- **Network and credential safeguards:** an unrouted/non-NAT management bridge,
  a separately guarded LiteLLM egress path, dynamic Incus DNS/DHCP host-firewall
  integration, ownership checks and fail-closed guest launcher behavior.
  A configured boundary is not proof of actual pilot-host isolation.
- **Reproducible operator and development workflows:** read-only diagnostics,
  documented deployment/acceptance procedures, hermetic validation and CI,
  Nix packaging, and human-gated release tooling.

**Pre-release integration status:** Narrow, default-off OpenCode Go session and
User-Agent forwarding has merged ([#456](https://github.com/blevinn/aginctus/issues/456)).
The OpenCode CLI buffered-SSE source fix and regression tests have also merged
([#542](https://github.com/blevinn/aginctus/issues/542)), but the patched
runtime's decisive buffered validation and live pilot inference remain pending.

## Compatibility and upgrades

- **Intended environment:** a trusted, single-operator Linux/NixOS host with
  flakes enabled and an initialized local Incus installation. The bundled
  Herdr and OpenCode guest images are NixOS **containers**; the v0.1 OpenCode
  image is not an independently validated VM image or a cross-platform
  workload runtime.
- **Installation:** the Nix package/module is the preferred NixOS path. The
  release workflow is designed to produce a standalone **Linux amd64 CLI**
  archive and SHA256 checksums, but those tagged artifacts have **not yet**
  been generated or approved. No ARM binary, artifact signing or SLSA
  provenance is promised in v0.1.
- **Host authority:** NixOS firewall reconciliation has an independently
  reviewable enable/disable setting and is not necessarily read-only on
  activation. Incus reconciliation and gateway activation have separate
  opt-ins. Existing operator authorization and a reviewed firewall/egress
  policy are prerequisites; do not enable host mutations just to test notes.
- **Existing state:** protect persistent Herdr SSH identity, LiteLLM/PostgreSQL
  state and runtime credentials. Keep a known-good source pin and backups.
  Reverting a Nix flake pin does not automatically roll back live Incus
  resources, schemas or credentials; state recovery requires its own plan.
  No automatic migration into a dedicated Incus project is part of v0.1.
- **Upgrade boundary:** v0.1 is the initial release candidate, not a promise
  of safe in-place migration from arbitrary development snapshots. Operators
  should explicitly review changes and pin the eventual immutable
  `v0.1.0` tag only after publication.

### Known limitations and explicit deferrals

- **Security model:** the host and Incus administrators are trusted. NixOS
  containers share the host kernel. The v0.1 management bridge is shared,
  not segmented per workload; bearer keys transit the private bridge over
  HTTP. Runtime metadata, permissions and network policies require actual
  deployment checks, not solely successful configuration rendering.
- **Deferred features:** v0.2 capabilities are outside v0.1's supported scope
  ([#173](https://github.com/blevinn/aginctus/issues/173)).
- **Experimental testenv:** Opt-in disposable NixOS VM test infrastructure has
  merged into the source tree, but combined Herdr/OpenCode/LiteLLM nine-phase
  synthetic acceptance is incomplete ([#531](https://github.com/blevinn/aginctus/issues/531)).
  Further testenv development is suspended until after v0.1; these component
  tests do not replace live pilot release acceptance.
- **No production-readiness or security-audit claim:** acceptance is for an
  operator-approved pilot lab, not a hardened multi-tenant platform.
