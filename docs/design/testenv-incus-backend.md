# Testenv persistent VM backends: Incus MVP (v0.2)

Status: **design accepted; implementation incremental**. Tracks [#475](https://github.com/blevinn/aginctus/issues/475) and #476–#479. This document describes **proposed** backend behavior, not proof that it has been deployed or that the guest isolation has passed KVM acceptance.

## Scope and separation of concerns

The NixOS test-driver batch harness (#446–#454) remains the opt-in operator CI backend for deterministic `just test-vm-*` / `aginctus testenv vm test` scenarios. Its Python driver is a host process; it is **not** an agent-safe interactive terminal.

The **persistent** `aginctus testenv vm` lifecycle should use the native `VMBackend` contract. Only `incus` is admitted in v0.2. A future backend may implement the same operations without changing CLI commands, MCP schemas or ownership checks.

```text
human / coding agent
       | typed CLI or stdio MCP, default deny mutation
       v
trusted testenv policy/control service
       | authorization, pinned image, run ID, quotas, TTL
       v
VMBackend interface (Incus in v0.2)
       | restricted local Incus API, never directly given to agent
       v
dedicated disposable worker Incus daemon
       | project: aginctus-testenv; isolated host storage/network
       v
outer NixOS VM with working incus-agent
       | guest root; testenv exec uses Incus VM agent
       v
inner Incus + Aginctus + synthetic integration fixtures
```

This structure deliberately reuses Incus for instance lifecycle, disk/snapshots, QEMU management, guest-agent command execution, quotas and recovery. It does not reuse the abandoned direct-QEMU/cgroup/QGA code (#464–#474, all closed without merge).

## Provider-neutral contract

`VMBackend` declares `Create`, `Status`, `Exec`, `Snapshot`, `Reset`, `Destroy`, `ListOwned` plus explicit `Capabilities`. Backends either implement an optional operation or return `ErrUnsupportedAction`; never silently replace snapshot/reset with destructive re-creation. Public `VMRef` contains backend, project/namespace, instance, random run ID and image fingerprint. **The handle is not an authorization token.** The backend must re-read resource ownership/generation and immutable run metadata before state change.

`VMCreateSpec` is generated by trusted worker configuration, not a raw MCP request. MVP policy: `incus`, the dedicated project `aginctus-testenv`, lowercase immutable SHA-256 image fingerprint, 1–2 vCPU, 512–5120 MiB memory, 8–32 GiB root disk and TTL of 1 minute–2 hours. No outer NIC by default. A backend-specific adapter validates these limits **again** rather than trusting client validation.

Future backend support can extend the registry with provider-specific names and capability/namespace validation without altering high-level VM operations. Do not force other providers to emulate Incus projects; adapter-specific namespace rules will be policy.

`aginctus testenv vm backend [incus]` is the first implemented read-only discovery path. It **does not open Incus or claim provisioning is available**. Both `vm backend qemu` and unsafe arguments are rejected.

## Incus control-plane and project security

For MVP, install a **dedicated worker Incus daemon** on a separate disposable KVM host (or separately isolated worker), rather than sharing the pilot operator's unrestricted Unix socket. The trusted Aginctus service is the sole daemon client. Coding agents must not join `incus-admin` or receive the daemon's Unix socket, admin certificates, or arbitrary `incus` CLI access. **Incus project scoping by itself is insufficient if the caller has full daemon-admin authority.**

A dedicated `aginctus-testenv` project must be `restricted=true` with allowlisted storage pool, `features.profiles=true` as appropriate and strict limits: `limits.instances`, `limits.virtual-machines`, `limits.cpu`, `limits.memory`, `limits.disk` (where supported by pool). Require `restricted.virtual-machines.lowlevel=block`, managed root disk only, no host-path disks, PCI/USB/unix-char/proxy/physical NIC passthrough, and no arbitrary profiles or user-provided `raw.qemu`.

Outer VM needs **nested virtualization** only if tests create inner VMs. Where Incus project restriction permits `restricted.virtual-machines.nesting=allow`, scope it to the dedicated project and test the actual hardware/KVM exposure. The inner test environment must not be able to reach the outer host Incus socket.

The image must be an immutable NixOS Incus **VM image** containing `incus-agent`, the guest-local Incus daemon, Btrfs test support and known Aginctus packages. Do not use the `run-nixos-vm` QEMU launcher as an Incus image or treat mutable `images:nixos/latest` as a pinned artifact. Import the pinned image into the test project using trusted worker reconciliation, then launch by fingerprint, not by arbitrary remote.

## Operations and failure model

1. **Create:** mint cryptographic run ID and an owner/generation marker in trusted state; validate the project's restrictions and limits, image fingerprint, root volume quota and no NIC before calling Incus. Create a uniquely named VM with fixed devices/profile; re-read it after creation. Name collision or preexisting foreign metadata fails closed. No implicit adoption.
2. **Start/Status:** start through Incus; wait for `incus-agent` readiness with a finite deadline. Incus "running" does not mean guest service ready or inner Incus initialized.
3. **Exec:** allow argv-array commands inside the *guest*, never a host Python or shell interpreter. Enforce caller authorization, argv count/bytes, runtime/output size limits and redaction; distinguish a nonzero guest status from transport failure.
4. **Snapshot/Reset:** use Incus snapshots within run scope when supported; check snapshot/generation ownership. Reject unsupported capabilities explicitly. Reset must not affect unrelated disks/volumes.
5. **Destroy/GC:** expire by trusted TTL, enumerate only controlled project and ownership markers, stop/delete via Incus operations, and re-read instance + root volume/snapshots to verify removal. On failure, write an honest `cleanup:not_verified` receipt; never delete foreign instances based solely on prefix matches. Resume cleanup after daemon restart, control service crash, or worker reboot via independent timer.
6. **Evidence:** include backend, image fingerprint, project, run identity, timestamps, guest readiness, synthetic-vs-live classification and verified cleanup result. Never echo guest/provider secrets to journal or MCP.

### Validation gates

Hostless: Go contract/fake tests; Nix evaluation of pinned image/worker policy; negative tests for foreign owners, missing project restrictions, mutable images and attempts at host-device passthrough. Disposable KVM worker: nested guest Incus, Btrfs, `incus-agent` readiness, storage/network isolation, snapshots, TTL recovery after SIGKILL/reboot, failed cleanup reporting. Pilot host: **no privileges or configuration changes**.
