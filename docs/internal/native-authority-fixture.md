# Native authority fixture handoff

This is an offline, same-UID implementation of the state and execution contracts in [ADR 0006](../adr/0006-environment-incus-authority.md). It does not establish project principal authentication, production fencing, or authority to deploy. The installed CLI still uses the existing read-only project-state path.

- The optional `Candidate.Gateway` is part of the canonical accepted digest. It pins PostgreSQL and LiteLLM OCI source, platform, manifest, config, Incus fingerprint and alias, existing pools and network references, gateway running/stopped intent, and the credential version. It carries neither secret values nor raw Incus devices. Exact physical service and volume identities are derived using the gateway domain's environment identity function. Select existing host-approved pools/networks and reverify them independently. The diff reports gateway changes without the field values.
- `LocalProjectStateStore.PromoteLocalCandidate` takes a trusted actor-bound promotion callback. It checks the whole detached candidate, expected full revision (zero for genesis), and fresh scope before touching the store and again under the existing CAS lock before publication. A rejected promotion cannot publish the pointer. It can leave an immutable orphan that is not accepted history.
- `orchestration.LocalNativeExecution.ExecuteLocalNative` runs A with a pinned accepted candidate. Its `Bind` callback receives the independently checked candidate and the gateway fragment. For apply, CAS and competing fixture executors share the existing per-environment lock; dry-run needs no lock file and rechecks the read authorization and revision before returning results. The actor-bound callback receives distinct inspect/execute/submit requests. For each effect the engine checks the exact stage and logical target, and the fixture bridge checks actor and pin again after journaling and before submission. Domain ownership, preconditions, incarnation and ETag checks are still required at the SDK boundary.
- Gateway stage IDs are `gateway-image` → `gateway-volume` → `gateway-instance` → `gateway-runtime`. Select the prerequisite prefix in the plan; each prerequisite needs A's required postcondition. Pair stages target `postgres` or `litellm`, the volume targets `database`, and workload effects target their accepted workload ID. Gateway starts require affirmative running intent; stops require explicit stopped intent. Keep B's pair preflight and order (including PostgreSQL readiness before starting LiteLLM, and LiteLLM before PostgreSQL on stop). Resolve these logical IDs only through bindings derived from the pinned candidate, never through arbitrary SDK arguments.
- The journal syncs an `uncertain` record before submission, then records `applied` only after a successful operation return. `open` means the invocation's return was not recorded; `completed` means the engine returned successfully, not that resources are still ready. Use the fixture CLI `operations` to discover IDs after an interruption and `operation --operation-id …` to read exact historical evidence. Both require an explicit `--state-dir`, `--server-id`, `--project`, and `--environment`. Recovery re-observes; these commands never replay effects.

The same-UID fixture does not establish a trusted remote writer/actor topology or approve production writes. See [#696](https://github.com/blevinn/aginctus/issues/696) and [#704](https://github.com/blevinn/aginctus/issues/704).

## B gateway join

Bind `LocalNativeExecution.Bind` to `gateway.BindAcceptedGateway` with a trusted selected-project SDK, the immutable OCI metadata resolver, and independently verified prior image acquisition evidence. The SDK is checked against the accepted server/project. The fixture authority must independently approve the existing networks and pools. For missing images, the image stage previews and authorizes the pull and alias separately (`postgres`, `postgres-alias`, `litellm`, `litellm-alias`). Unknown provenance, orphan imports, daemon-wide fingerprint collisions and stale or foreign aliases fail closed. Same-invocation acquisition evidence is ephemeral; a later invocation requires independently verified evidence, not just the accepted image intent or observed alias.

The volume and guest stages detect known collisions during global preview even when image or volume prerequisites are absent. The stopped pair is the last implemented stage. Selecting `gateway-runtime` fails before effects, even when the candidate requests running. A successful fixture apply proves observed infrastructure and stopped guests, not authentication or readiness. The offline stopped-pair VM exercises real Incus reuse, volume and guest creation. The hermetic join exercises image acquisition and alias creation via the real domain primitives with injected SDK effects.

## C lifecycle join

Each selected workload must have `workloads[].native` with exactly `runtime`, `storagePool`, and `managementNetwork`. The canonical owner is `acceptedstate.WorkloadSpec.Native`. The existing workload ID, instance name/type, fingerprint, profiles and `ensureRunning` still come from the same accepted workload. A candidate without `native` can still be read or promoted but cannot produce a D/C fixture reconcile. The fixture also requires explicit empty profiles for lifecycle reconcile; it does not approve inherited attachment policy.

Optional `Candidate.Herdr` (`herdr`) pins `instanceName`, `imageFingerprint`, `storagePool`, `managementNetwork` and explicit `allowStateBootstrap`. C derives the container shape, system-volume class/name and mount point, and reconciles Herdr to running. There are no configurable workspace paths, image aliases, arbitrary devices or host bridge settings. The accepted bootstrap bit alone cannot create a disk: set `LocalNativeExecution.BootstrapHerdr` for that invocation, pass the resulting bool to C's `Herdr.CreateState`, and separately authorize each effect. C still must independently verify retained state, absence, and incarnation. Deployment or migration history is not inferred from an absent volume.

`LocalNativeExecution.BindLifecycle` has signature `func(environment.Candidate, orchestration.NativePlan, bool) (orchestration.NativePlan, map[string]orchestration.NativeResourceBinding, error)`. The supplied candidate is a detached full accepted body; the plan includes only selected C stages/edges. Build `nativelifecycle.Selection` and return the actual result of C's `Build` using these inputs:

| C input | Source |
| --- | --- |
| `workload.Spec.ID`, `Name`, and `Isolation` | Accepted workload selected by stage ID; map `virtual-machine` to `vm`, `container` to `container`. |
| `workload.Spec.Runtime`, `StoragePool`, and `ManagementNetwork` | The same workload's `.Native` fields. C reads the fingerprint, profiles, and running intent from the accepted workload. Leave the legacy `ImageAlias` and `Network` fields unset. |
| `Herdr.Spec.Name`, `StoragePool`, and `ManagementNetwork`; `Herdr.ImageFingerprint` | `Candidate.Herdr`. Leave legacy alias and network config unset. |
| `Workload.Operation` and `Herdr.Operation` | `native.ReconcileInstance`. D does not expose C's separate start, stop, or remove operations. |
| `Bridge.Spec`, host reader, verifier, restricted project SDK session and TLS pin | Independent capabilities. `Bridge.Spec.Name` must equal the common accepted management-network reference; none of the host policy or credentials are sourced from the candidate. Verify exact pool/network/instance references independently and again at use. |

D compares C's returned revision, stage IDs, kinds, internal edges and exact binding coverage before observations. It rejects unpinned workloads, mismatched bridge names among selected attachments, missing bridge/retained-volume edges, orphaned Herdr stages and active lifecycle checks. It never invokes an Apply closure for the management-network stage. Only the final plan retains cross-stack edges; the lead composes them and the authorizer sees that exact plan. The composer is trusted code: graph equality cannot attest to opaque callback contents. Derive all C typed inputs from the supplied candidate as shown above, and pass C's actual result instead of copying the expected graph over it.

The canonical UUID-derived gateway guest names are reserved across all candidates, including candidates without gateway intent and environments sharing the project. Workload and Herdr declarations using these names fail validation. This prevents both domains from independently planning a create for the same absent Incus instance. A conflicting existing name requires explicit resolution; the fixture does not rename, adopt or delete instances. The mixed hermetic test runs both composers under one revision, checks full-plan denial and both cross-domain edges, and recovers from a lost workload create result without repeating completed gateway effects or rewriting the failed journal.
