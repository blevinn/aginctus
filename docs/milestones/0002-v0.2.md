# v0.2 milestone: controlled workload access

Status: **planned**. This is the repository's v0.2 release description,
not a claim that these features are implemented.

## Goal

Extend the working v0.1 Herdr/OpenCode/gateway vertical slice with
two explicit host-controlled access boundaries:

1. **Segmented networking:** separate Herdr management, agent workload,
   and AI gateway traffic with precisely permitted flows. See
   [issue #119](https://github.com/blevinn/aginctus/issues/119).
2. **Live host workspace sharing:** let a managed coding workload edit an
   explicitly granted host checkout in place, without copying or syncing it,
   subject to optional host workspace-root policy. See the
   [workspace sharing design](../design/workspace-sharing.md).

v0.1 may use a shared management network and a guest-local/test repository;
neither v0.2 feature should retroactively block v0.1 acceptance.

## Networking workstream

- Define management/workload/gateway trust boundaries and address discovery.
- Reconcile network attachments and narrowly permitted Herdr, SSH, model API,
  and gateway-upstream flows; constrain agent egress.
- Verify both allowed and forbidden flows, lifecycle/reconciliation, and
  migration from v0.1's shared `aginctus-mgmt` network.
- Preserve workload connectivity required for Herdr control and inference.

## Workspace sharing workstream

- Introduce optional per-workload `workspace.source`, `target`, and
  `access`; default to no mount, `/workspace`, and read-only access.
- Introduce host-admin-controlled `/etc/aginctus/policy.json` and NixOS
  `services.aginctus.workspace.allowedRoots`, with `null` = unrestricted
  explicit grants, `[]` = deny all, nonempty list = approved roots.
- Validate host canonical paths, protected locations, guest targets, allowed
  roots, and explicit access before applying devices. Do not permit ordinary
  workload/config overrides or `--force` to weaken host policy.
- Mount live with Incus disk devices into an unprivileged container;
  prefer `shift=true` when supported and ensure the guest `agent` has
  safe, usable permissions. Never silently rewrite host file ownership.
- Reconcile drift, revocation, dry-run, ownership, and teardown without
  deleting host workspace contents or overwriting unrelated Incus devices.
- Prove bidirectional edits and read-only denial on a disposable host
  checkout; document unsupported identity mapping and VM limitations.

## Release acceptance

- [ ] Herdr/client/workload/gateway traffic crosses only documented,
      tested network boundaries; intentionally disallowed flows fail.
- [ ] A managed OpenCode **container** can edit a host checkout live through
      an explicit read-write workspace grant with safe effective identities.
- [ ] Unshared workspaces remain invisible; read-only mounts prevent guest
      writes; path allowlist states and protected paths are enforced.
- [ ] Repeated reconciliation is idempotent, noncompliant/stale mounts are
      observable and revocable, dry-run is non-mutating, and teardown leaves
      host files intact.
- [ ] NixOS policy/workload configuration, migration guidance, and
      reproducible disposable-Incus validation are documented.

## Out of scope

Host workspace synchronization or copy-on-write overlays, multi-host sharing,
automatic UID/GID/ACL manipulation, arbitrary multiple mounts, privileged
containers, and general VM workspace support are not v0.2 acceptance gates.
VM filesystem sharing can reuse the workload intent later after independent
VirtioFS/9p and permission validation. This work does not imply deployment of
a new API service or UI.

## Parallel, non-blocking architectural refactor

Following v0.1 acceptance, work **may begin** on the long-running native Incus reconciliation migration ([ADR 0002](../adr/0002-native-incus-reconciliation.md), [design](../design/native-incus-reconciliation.md), [epic #153](https://github.com/blevinn/aginctus/issues/153)). This refactor is **not part of v0.2 release acceptance**: existing Apply/Compose drivers remain valid and must continue to support networking and workspace sharing. Native implementation and eventual cutover can continue into v0.3 or later. Do not delay v0.1 or v0.2 to complete it.
