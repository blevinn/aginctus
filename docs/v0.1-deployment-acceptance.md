# v0.1 deployment and acceptance runbook

This is the operator handoff for the single-host NixOS, Herdr, OpenCode and
private LiteLLM vertical slice. It is a **procedure to validate**, not a new
end-to-end PASS. [Release #118](https://github.com/blevinn/aginctus/issues/118)
owns acceptance; [releasing](releasing.md) owns versioning and publication.
The five functional criteria have live pilot evidence at
`57c2da642f5bcb400bdc4430b8102c2a181e877b`. Fresh-host execution of this whole
procedure, including its repeat and cleanup, was **not executed for v0.1**.
On 2026-10-31 the release owner explicitly deferred that unrun fresh-host
reproducibility gate to [v0.2 #580](https://github.com/blevinn/aginctus/issues/580)
while requesting v0.1 release preparation. The procedures below remain useful
for future deployments but are **not evidence of a complete fresh-host PASS**.

## 1. Select a host, revision and authority

- Use an approved **x86_64-linux NixOS host**, flakes and the locked Aginctus
  inputs. The current Herdr/OpenCode images are containers, not VM images.
  aarch64 runtime acceptance is not established. Build dependencies and OCI
  images require disk space and trusted download access; the topology VM uses
  8 GiB RAM and 32 GiB disk, not a measured minimum for a production host.
- Use an initialized local Incus daemon and an explicitly selected existing
  storage pool. Check `incus storage list` and the local remote/project before
  mutations. The topology VM uses the locked `pkgs.incus`, not the default LTS
  package; OCI NIC gateway controls are required. Prefer that exact package.
- v0.1 client/workload operations use `default`; Compose uses
  `gateway.compose.project` (default `aginctus-gateway`). The v0.2 `incus.project`
  setting does **not** redirect these operations. Do not migrate projects here.
- Reserve nonoverlapping management and egress CIDRs after checking **all**
  host routes, Incus projects, leases and NICs. Reserve the LiteLLM static
  egress address outside DHCP. Do not copy private pilot addresses.
- Select one administrative principal and one runtime state root. The NixOS
  reconciler uses `/var/lib/aginctus/state`; an interactive user's default
  state is different. Run gateway registration/issue/revoke with the same
  principal and `XDG_STATE_HOME` as gateway initialization. A 401 is not
  permission to initialize a second master key.
- Save a private inventory of names, ownership, storage attachments, image
  fingerprints, public SSH fingerprints and selected package revision. Never
  publish expanded Incus config, raw logs, transcripts or credential files.

Pin the consuming host's Aginctus flake input to
`github:blevinn/aginctus/57c2da642f5bcb400bdc4430b8102c2a181e877b` for this
acceptance baseline and commit its lockfile through the host's own review.
Retain the previous host pin. This is a development revision, **not** a
`v0.1.0` tag. A later release candidate requires an explicit evidence delta.

From an isolated checkout of that revision, these commands are hostless:

```sh
nix --quiet develop --no-update-lock-file -c just check-all
nix --quiet build --no-update-lock-file --no-link .#aginctus .#herdr-client .#opencode-workload
git rev-parse HEAD
```

Review [configuration precedence](configuration.md) and the generated units.
Use the [NixOS module example](configuration.md#nixos-module) with these
deliberate choices, rather than activating its automatic reconciliation:

| Option | Choice for staged deployment |
| --- | --- |
| `services.aginctus.enable` | `true`, importing `aginctus.nixosModules.default` |
| `services.aginctus.reconcile.enable`, `.gateway` | Both `false`; no implicit fleet/gateway apply |
| `services.aginctus.images.herdrClient.enable`, `.opencodeWorkload.enable` | Initially `false`; enabling imports/repoints aliases at activation |
| `services.aginctus.firewall.enable` | Initially `false`; enable only in approved host-policy activation |
| `services.aginctus.firewall.egress.enable` | `true` only with approved firewalld boundary and management firewall enabled |
| `settings.infrastructure.herdr.storage.pool`, `settings.workloads.dev.storage.pool` | The reviewed pool; workload type `opencode`, isolation `container` |
| `settings.gateway.credentials.storage.pool` | Explicit freeform setting for gateway credential volume |
| `settings.incus.management.network.ipv4` | Explicit reviewed CIDR, `nat = false`, `routing = false`, `dhcp.gateway = "none"` |
| `settings.incus.management.network.ipv6.address` | `"none"` |
| `settings.gateway.egress.network` | Explicit reviewed bridge name/CIDR and DHCP policy from [egress guide](gateway-egress-network.md) |
| `settings.gateway.egress.ipv4.address` | Reserved static LiteLLM egress CIDR |
| `settings.firewall.egress.uplinkZone` | Actual zone of the unique default IPv4 uplink; empty refuses grants |
| `settings.gateway.litellm` | `selectiveGoForwarding = true`, `forwardClientHeaders = false` |
| `settings.gateway.images.litellm` | Reviewed immutable reference below |

```text
ghcr.io/berriai/litellm:v1.103.0@sha256:bd089afdcd35b894b14a93f9743cdc8b591f82da1a38dd43a010a7b0c9de5fd7
```

The default PostgreSQL image is `docker.io/library/postgres:17-alpine`.
Record the actually imported fingerprint; this mutable tag is **not** a
fully pinned OCI supply chain. Do not invent a digest or infer publisher
authentication from a content hash. Production PostgreSQL upgrade/restart
and aarch64 remain separate limitations.

**Activation approval:** a host administrator reviews the generated NixOS
generation, Incus package, image services, management DNS/DHCP rules and
[six-object egress boundary](gateway-firewalld-egress.md) before switching.
The boundary requires retained nftables-owned filtering, strict DNAT handling,
DROP during reload and no flowtable/whole-ruleset bypass. Review effects on
SSH, Tailscale and existing published ports. A build is not activation approval.
Do not change `system.stateVersion`. No activation command in this runbook is
authorization to apply it to the working pilot.

## 2. Fresh deployment without provider credentials

Only on a **new approved deployment**, after storage/network ownership and
the permanent default-deny firewall are established:

1. Choose one image importer. Either enable the module's image services in an
   approved generation and require both units to succeed, or use the repository
   image workflow below. Do not run competing system/user import owners.
2. Inspect dry-runs, apply the management network and then deploy the gateway
   under the selected state owner. Confirm the driver's required Incus HTTPS
   listener is local loopback only; `doctor --fix` changes host configuration
   and requires separate approval. Never expose the daemon publicly.
3. Apply client/workload resources and check readiness independently.

```sh
# Alternative manual importer, mutates local image aliases:
nix --quiet develop --no-update-lock-file -c just build herdr-client
nix --quiet develop --no-update-lock-file -c just update image herdr-client
nix --quiet develop --no-update-lock-file -c just build opencode-workload
nix --quiet develop --no-update-lock-file -c just update image opencode-workload

aginctus network apply --dry-run
aginctus herdr client apply --dry-run
aginctus workload apply dev --dry-run
aginctus gateway validate
aginctus gateway render

# Mutating, fresh deployment only, using the approved configuration/state owner:
aginctus network apply
aginctus gateway apply
aginctus herdr client apply
aginctus workload apply dev
```

For a root-owned NixOS gateway, run the gateway operation in an approved root
terminal with `XDG_STATE_HOME=/var/lib/aginctus/state`. Do not use a shell
user's state and later switch to root for registration. Initialization generates
and reuses protected `aginctus/gateway/<id>/secrets.json` (directory 0700,
file 0600). Preserve master/salt/database values and all gateway storage.
Never seed them through Nix settings, CLI arguments or unit environment text.

The gateway apply initializes LiteLLM/PostgreSQL and resource attachments;
it does not register a model, prove readiness or recreate existing guests
at a new image alias. The ordinary apply path is **not an existing-pilot
upgrade helper**. See section 7 before retrying any partial deployment.

The Herdr client ensure creates/verifies its owned `state-system` volume.
Confirm the canonical and bind mounts for `/var/lib/herdr` and
`/var/lib/aginctus/ssh` using [persistent-state readback](herdr-persistent-state-volumes.md).
On a genuinely new empty client, after separate identity-generation approval:

```sh
incus --project default exec aginctus-herdr -- aginctus-ssh-client-identity ensure
aginctus herdr authorize dev
aginctus herdr pin-host dev
aginctus herdr register dev
incus --project default exec aginctus-herdr -- herdr machine status aginctus-dev --json
incus --project default exec aginctus-herdr -- herdr --machine aginctus-dev workspace list
```

Names here are the module defaults. Substitute only configured, verified owned
names. `authorize` does not generate an identity. An absent identity on a prior
deployment is a recovery event, not a fresh bootstrap. Changed SSH pins,
authorization or machine profiles fail closed; follow [Herdr recovery](herdr-machine-registration.md).

## 3. Read-only readiness and isolation

Use the exact configured names/project, never raw expanded configuration:

```sh
aginctus --version
aginctus gateway status
aginctus workload status dev
nix --quiet develop --no-update-lock-file -c just check preflight-report pilot-topology
incus --project aginctus-gateway exec postgres-1 -- pg_isready -U litellm -d litellm
incus --project aginctus-gateway exec litellm-1 -- python3 -c \
  'import urllib.request; assert urllib.request.urlopen("http://127.0.0.1:4000/health/readiness", timeout=5).status == 200; print("PASS: readiness")'
```

Independently check management NAT/routing disabled, DHCP gateway `none`, no
IPv4 default in client/workload/PostgreSQL, and exactly one LiteLLM default on
its **egress** NIC. OCI PostgreSQL and LiteLLM management NICs must suppress
their gateways independently of bridge DHCP. [Management route migration](management-dhcp-gateway.md)
explains this distinction and safe readback. Confirm LiteLLM-to-PostgreSQL
hostname TCP and workload-to-private-gateway TCP, not just process status.

Audit the [selective bundle](selective-go-forwarding.md#inspect-deployed-delivery-without-inference)
against this exact package and independently mapped OCI/Incus fingerprint.
File hashes/readiness are not proof of **active** callback loading; record
fresh-process provenance and separately authorized request evidence.

Before a credential is delivered, review runtime/permanent six-object policy,
actual kernel traversal/predicates, alternate zones and DNAT safeguards.
Use [guest controls](acceptance-opencode-preflight.md) with a host-confirmed
public listening positive control. Require private gateway positive, workload
direct-public negative, LiteLLM public TCP443 positive/TCP80 negative and a
listening host-service negative. Record IPv6 `ENETUNREACH` as no-route,
**not** routed IPv6 firewall enforcement. A timeout is not exact DROP attribution.
Disruptive reload/restart/reboot and established-flow withdrawal need their
own disposable evidence or explicit human limitation acceptance.

## 4. Protected model registration and deliberately limited issuance

This stage requires separate human approval for administrative writes and the
actual provider entitlement/model. Do not read existing pilot secrets as part
of validating this document. Use [registration](gateway-api-key-pilot.md) and
[key lifecycle](gateway-workload-key-pilot.md) with the initialized gateway's
principal/state root. Stage a provider credential in a caller-owned 0600
nonsymlink regular file in a 0700 directory outside Git/Nix/history. It stays
in the gateway, never the workload.

Set `ENDPOINT` to the independently observed **private numeric IPv4** HTTP
endpoint on port 4000, and `PROVIDER_KEY_FILE` / `WORKLOAD_KEY_FILE` to protected
absolute paths. The latter must not exist. These are private local variables,
not values to paste into GitHub. Run the previews first:

```sh
python3 scripts/gateway/register-openai-model.py --endpoint "$ENDPOINT" \
  --provider opencode-go --alias aginctus-go-pilot --source openai/gpt-6-luna
python3 scripts/gateway/manage-workload-key.py --endpoint "$ENDPOINT" \
  --alias aginctus-go-pilot --output "$WORKLOAD_KEY_FILE"

# Each mutation requires deliberate approval; do not blindly repeat registration:
python3 scripts/gateway/register-openai-model.py --endpoint "$ENDPOINT" \
  --provider opencode-go --alias aginctus-go-pilot --source openai/gpt-6-luna \
  --upstream-key-file "$PROVIDER_KEY_FILE" --apply
python3 scripts/gateway/manage-workload-key.py --endpoint "$ENDPOINT" \
  --alias aginctus-go-pilot --output "$WORKLOAD_KEY_FILE" --issue
aginctus workload gateway provision dev --model=aginctus-go-pilot --key-file="$WORKLOAD_KEY_FILE"
nix --quiet develop --no-update-lock-file -c just check preflight-report opencode-runtime
```

The issuer requests one alias, one hour, $1 gateway budget, 5 RPM and concurrency
one. Verify missing/invalid discovery tokens rejected, selected key sees only
the alias and cannot administer keys. The existing `--auth-only` smoke makes
no inference. Provisioning discovers one owned running LiteLLM private address;
it overwrites guest runtime files and therefore requires approval even on repeat.
Verify guest directory/file ownership and mode without reading key bytes.
Private management HTTP is plaintext within the trusted bridge.

**Revocation plan is mandatory before issuance:** on success, failure or
interruption, revoke the exact temporary key using the same protected file:

```sh
python3 scripts/gateway/manage-workload-key.py --endpoint "$ENDPOINT" \
  --alias aginctus-go-pilot --output "$WORKLOAD_KEY_FILE" --revoke
```

Success includes subsequent authentication rejection and host-file removal.
If uncertain, retain the file privately and investigate remote key state;
never retry ambiguous issuance or delete the only revocation handle. Expiry
is a backstop, not proof of revocation. Remove the **matching retired guest
copy** only after confirmed revocation, using section 6's guarded cleanup.
No script can guarantee remote revocation when the gateway is unavailable;
keep signoff pending until verified.

## 5. Optional genuine coding smoke, separately authorized

The following is a **manual checklist**, not a turnkey live adapter and not
an authorization to spend. It avoids assuming Go exists in the guest PATH.
Run under the workload's non-root `agent` through the managed Herdr client.
Use a new private guest-local directory and a unique run label, record their
mapping in a trusted operator-owned record, and preserve unrelated workspaces.

1. Allocate a fresh directory with guest `mktemp -d` beneath `/home/agent` as
   `agent`, mode 0700. Record its exact returned path privately. Create only
   `calc.sh` and `test.sh` there using authenticated Incus stdin. `calc.sh`:

   ```sh
   #!/bin/sh
   add() { result=$(($1 - $2)); }
   ```

   `test.sh` (invoke with `sh ./test.sh`; no executable-bit assumption):

   ```sh
   #!/bin/sh
   set -eu
   . ./calc.sh
   add 3 4; test "$result" = 7
   add 8 5; test "$result" = 13
   printf '%s\n' 'PASS: arithmetic tests'
   ```

2. Independently require the initial test to fail. Record SHA-256 of `test.sh`
   before the task. Confirm no other files, mounts or provider credentials were
   staged. Save the initial two file contents as public fixture evidence.
3. In the **managed client**, run `herdr --machine aginctus-dev workspace create
   --cwd GUEST_PATH --label UNIQUE_RUN_LABEL --no-focus`. Record the actual
   `result.workspace.workspace_id` and `result.root_pane.pane_id`; never guess
   pane IDs. Use the pinned [Herdr lifecycle command shapes](acceptance-opencode-herdr.md).
4. Start `herdr --machine aginctus-dev agent start UNIQUE_AGENT --kind opencode
   --pane OBSERVED_PANE_ID --timeout 90000`. Inspect the native pane. Prompt the
   agent to **read both files, fix only calc.sh, run sh ./test.sh, explain the
   result and finish**. Do not manually apply the fix or manufacture sessions.
5. Bound the wait and spending. Herdr `idle`, `done`, prompt timeout or a zero
   CLI exit is not completion proof. The pilot observed delayed readiness and
   rate-limit retries. Inspect native Read/Edit/shell tool records and final
   terminal text; for JSON mode require `step_finish.reason == stop`.
   On uncertainty inspect the existing task, not a duplicate prompt/run.
6. Independently execute `sh ./test.sh` in the exact guest directory as `agent`.
   Require PASS, expected addition-only diff and unchanged test hash. Confirm
   the **agent's** tool trace ran the test, not just the operator's verification.
7. From trusted gateway records, correlate native session(s), exact key hash,
   alias, request IDs and successful `aresponses` observations to the recorded
   workspace/run. Compare independent native IDs, not agent-printed claims.
   Preserve redacted receipts privately; never publish raw spend rows or pane
   transcripts. Record actual upstream evidence separately from provider billing.
8. Run section 6 on every outcome. Only independent task, gateway and cleanup
   observations together support acceptance. A failing native task is a failure
   even if a synthetic fixture passes elsewhere.

The generic [nine-hook dispatcher](acceptance-opencode-live.md) still requires
operator-reviewed fixture transport, credential checks and gateway evidence.
Its strict historical inspector expects run-ID in `end_user`; current live
native session/key/alias/request correlation does **not** satisfy that contract.
Do not weaken the inspector or emit success markers to pretend it did.

## 6. Independently checked teardown

Record cleanup obligations before creating anything. On interruption inspect
the exact run's state before continuing, in this order:

1. Stop only the observed owned agent/pane, then confirm it is no longer running.
   Inspect the workspace label and directory before close. Close only its
   recorded workspace ID. Query workspace list **and** the exact ID again;
   require ID/run-label absence. Conflicting `get`/`list` results need another
   readback, not an assumption. Preserve unrelated workspaces (including the
   pilot's unrelated `w8`).
2. Revoke the exact key with section 4's tool and require denied authentication.
   Independently require host key path absent, including dangling symlink.
3. Remove only `/var/lib/aginctus/opencode/workload-key` in the verified owned
   workload after confirming it is this run's retired key, a nonsymlink regular
   file owned `agent:users`, mode 0600. Run removal as `agent`; separately check
   both `! -e` and `! -L`. Do not remove a concurrently rotated/unrelated key.
   A provisioned config without a key must make the launcher fail closed.
4. After verifying exact directory ownership, stopped process and expected
   contents, remove only the two owned fixture files and `rmdir` the exact run
   directory. Unexpected files require inspection, never recursive broad cleanup.
   A second guest exec must check directory absence, including dangling symlink.
5. Record owned processes absent, workspace absent, fixture absent, remote key
   rejected and host/guest key files absent as **separate** observations. Service
   readiness and unrelated workspace inventory should remain intact. No teardown
   here removes guests, images, snapshots, persistent volumes or model aliases.

## 7. Repeat, failure recovery and rollback limits

| Step | Repeat/recovery contract |
| --- | --- |
| Image import | Same fingerprint is idempotent; changed alias does not upgrade running instances. Verify unit exit and alias fingerprint. |
| Network/client/workload apply | Inspect existing ownership and drift first. Partial failure may leave resources. Never add `--force` or delete foreign resources to get green. |
| Gateway initialization | Reuses protected runtime state. Lost state is recovery, not rotation. Keep master/salt, DB and storage attachments together. |
| Existing selective gateway | Compose does not fully converge image/env/config removal or rewrite running files. Use the [narrow migration plan](selective-go-forwarding.md#migration-activation-and-rollback), never broad apply as diagnostics. |
| Herdr identity/trust | Ensure only on approved new empty state. Preserve client volume, workload SSH identity and machine catalog; changed pins require reviewed recovery. |
| Registration/issuance | Inspect registry first. Ambiguous POST may have succeeded; do not automatically retry. Issue to a new exclusive file only after remote state resolved. |
| Coding smoke | Fresh label/path/key; inspect previous run cleanup before creating another. Reuse no unrelated workspace or fixture. |
| NixOS rollback | Restores declarations/packages, not deleted Incus data, aliases, DB migrations, credentials or external provider charges. |

For the working pilot, **retain the reconciler hold**. Its effective host
declaration is nonselective while the validated runtime is selective. Before
removing the hold or activating a generation, a human must review the exact
selective digest/config, state owner, generated units, persistent attachments
and narrowly scoped rollout/rollback. General provider/model reconciliation
is v0.2; that deferral does not make an unsafe apply acceptable.
